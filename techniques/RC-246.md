A user submits a natural language query to an NL-to-SQL application. The query is crafted to cause the LLM to generate SQL that includes injected clauses — UNION SELECT, subqueries accessing other tables, or stacked statements — rather than the simple, scoped query the application intends. The generated SQL is then executed directly against the database. Because the injection happens at the LLM output stage rather than a string concatenation stage, traditional SQL parameterisation does not prevent it: the model itself generates the malicious SQL.
