# AIHACKBins v10.9 — OWASP AITG Practical Testing Integration

Based on v10.8, with all 65 original RC identifiers, payloads, variants, lab data, design and routes preserved.

- Each RC includes an editorial testing access recommendation (black-box, grey-box or white-box), an objective, execution guidance, evidence interpretation and defensive checks.
- All 32 AITG baseline cards have collapsible execution, interpretation and defence guidance, alongside the original objective links and RC crosswalks.
- Glossary includes Black-box, Grey-box, White-box, SecAI, PrivacyAI, RespAI and AITG test method.
- New `data/aitg_testing_guidance.json` supports source auditing and offline checks.
- The static SPA and labs never connect to live AI systems. Research attribution remains separate from independent verification.
- Guidance is editorially paraphrased from the OWASP AI Testing Guide v1.0 (November 2025), not imported verbatim, and should be adapted to target scope.

## Limitations
The categorisation of required access is an editorial starting point; individual targets may require other access levels. The new methodology fields do not prove exploit success or that each original publication supports every adapted input. Browser regression still requires a passing supported Chromium run.
